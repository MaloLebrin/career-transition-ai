# 2026-10-13 — Pages d'erreur 403 et 429 (#74)

Les pages 404 et 500 étaient déjà en français ; il restait les refus d'accès. Les
middlewares de rôle répondaient un JSON 403 même à une visite Inertia (affiché dans
une modale brute), et il n'existait pas de page 429 hors requêtes Inertia.

- **403.** Nouveau `denyAccess` (`#utils/forbidden_response`) utilisé par les middlewares
  admin, conseiller, candidat, super admin et destinataire de notifications : page
  `errors/forbidden` (statut 403, message du refus) pour une visite Inertia ou une
  navigation `Accept: text/html`, `{ message }` en JSON pour les autres clients.
- **429.** Page `errors/too_many_requests` pour une navigation classique (page de
  statut du handler, comme 403/404/5xx) ; les requêtes Inertia gardent le flash + redirect back.
- **Front.** `ErrorPage` accepte les codes 403 et 429.
- **Tests.** Unit `forbidden_response`, matrice d'accès functional (page Inertia + JSON),
  Vitest `errors/forbidden` et `errors/too_many_requests`.
